# Rust conventions

Rust 2024 is the source of truth; Python 3.14 behaviour is the regression baseline for output.

## Layout
One Rust module per Python module: `src/hermes_harness/<pkg>/<mod>.py` became
`src/rs/<pkg>/<mod>.rs` (declared in `src/rs/<pkg>/mod.rs`, for example
`crate::core::task_reservation`), and `tests/test_<x>.py` became the integration test `tests/<x>.rs`,
which uses only the public API. Byte-for-byte parity applies to machine-consumed output (digests,
receipts, persisted JSON evidence, CLI JSON contracts) and to strings a test or caller matches on;
other diagnostics may differ. Underscore-private Python names that other modules
imported are `pub(crate)`; test seams use traits, `*_with` fns or in-module unit tests, never
`#[doc(hidden)]` pub items.

## Dependencies
std, serde (derive), serde_json, thiserror 2, sha2, hex, log 0.4, getrandom 0.2, rusqlite 0.32
(bundled), ureq 3 (rustls, platform-verifier, json), clap 4 (derive), rustix 0.38 (fs, net, process,
system; unix only), tempfile (tests only).

## Types
- `util::ordered_map::OrderedMap<V>` holds insertion-ordered dicts (state.json approvals, evidence,
  history) and keeps file order like Python. Known gap: a duplicated top-level key in a file read into
  a derived struct is rejected by serde (`duplicate field`), while `json.loads` keeps the last value.
  The harness never writes duplicates, so such files fail closed.
- Non-finite floats: serde writes `null` where Python's `json` writes `NaN`/`Infinity`. No serialised
  field holds a float that can be non-finite.
- `tests/pysource_parity.rs` checks the contract scanner against CPython `ast` over the frozen corpus in
  `tests/fixtures/pycorpus/`, pinned in `tests/fixtures/pycorpus/VERSION`. The test fails on a stale
  fixture by design; regenerate it with `tools/gen_contract_fixture.py`.

## JSON and digests (byte-identical to Python)
All helpers live in `crate::util` and return `Result<_, util::JsonError>`. Use them wherever Python
hashes or serialises JSON, picked by the Python call:

| Python | Rust | Used by |
|---|---|---|
| `dumps(v, sort_keys=True, separators=(",", ":"))` | `canonical_json` | most digests |
| `sha256(canonical)` | `json_digest` | default digest |
| `sha256(canonical + "\n")` | `json_digest_line` | task_reservation, multiagent/runtime, cyber_evaluation |
| `dumps(v, sort_keys=True)` | `sorted_json_spaced` | gateway_lifecycle, live_capability_broker |
| `dumps(v, sort_keys=True, indent=2)` | `pretty_json` | sorted reports |
| `dumps(v, indent=2)` | `pretty_json_ordered` | state, watchdog, orchestration, live_operator_report |

`sha256_hex`, `utc_now_iso` and `iso_utc` match `hashlib.sha256().hexdigest()` and
`datetime.now(UTC).isoformat()`. Never enable serde_json's `preserve_order` feature: sorted output
depends on `BTreeMap`. `tests/util_parity.rs` pins parity with a fixture generated by real CPython.
Invalid-relative-path errors quote with Rust `{:?}` (double quotes, `\u{..}` escapes), not Python repr.
Log lines keep the Python message shape but print Rust values: the broker rejection names the error
variant (`Denied`, `Io`, ...) and the watchdog prints `alive=true`/`false`. Nothing parses logs.

## Lints (CI denies all warnings)
clippy all + pedantic + nursery are `deny`. Also denied: `unwrap_used`, `expect_used`, `panic`, `todo`,
`indexing_slicing` (use `.get()`), `string_slice`, `float_cmp`, `dbg_macro`. `unsafe` is forbidden.
Every `pub` item needs a `///` doc comment (one line is fine). Mark pure getters `#[must_use]`, use
`const fn` where possible, take `&str`/`&Path` not `&String`/`&PathBuf`, no needless `clone()`, max
line width 100, functions under about 80 lines. Tests may use unwrap/expect/panic/indexing.
Each integration test starts with
`#![allow(missing_docs, clippy::unwrap_used, clippy::expect_used, clippy::panic, clippy::indexing_slicing)]`.
Private helpers are plain `fn` or `pub(crate)`, never `_name`.

## Style and standards
Idiomatic, allocation-aware Rust: iterators over index loops, `?` for propagation, `&[T]` params, no
global mutable state. Comments explain intent, not the port. Follow the
[Rust API Guidelines](https://rust-lang.github.io/api-guidelines/checklist.html) and rustfmt defaults;
where they conflict with byte-for-byte Python parity, parity wins and the code says why.
- Naming (C-CASE, C-CONV, C-GETTER, C-ITER): `as_`/`to_`/`into_` by cost and ownership; getters are
  `name()`; iterator methods `iter`/`iter_mut`/`into_iter`; constructors `new`/`with_*`.
- Traits (C-COMMON-TRAITS, C-DEBUG): public types derive `Debug`, plus `Clone`, `PartialEq`/`Eq`,
  `Default`, `Hash` when meaningful. Types holding secrets get a manual `Debug` that redacts them.
- Conversions (C-CONV-TRAITS): `From`/`TryFrom`/`FromStr`/`AsRef` for the obvious conversion;
  `Display` for anything users see.
- Errors (C-GOOD-ERR): one `thiserror` enum per module, `Send + Sync + 'static`; keep text matched by
  tests or callers; `#[source]`/`#[from]` keep the cause chain. No `Box<dyn Error>` in public APIs
  except trait seams.
- Docs (C-FAILURE): every fallible `pub fn` has `# Errors`; any fn that can panic has `# Panics`
  (production code should not panic).
- Validation (C-VALIDATE, C-NEWTYPE): validate at construction; prefer a newtype or enum over a
  stringly typed field when the value set is restricted, as long as the JSON does not change.
- Ownership (C-CALLER-CONTROL): borrow unless the fn stores the value; return owned data. Interior
  mutability only behind a documented seam.
- Visibility and seams: smallest visibility that works; seam traits have the fewest methods needed.
- Modules: no glob imports except `use super::*` in unit tests; import order std, external, crate.

The Python package, its tests, packaging and scripts were removed. The vendored corpus under
`tests/fixtures/pycorpus/` (date in `VERSION`) remains the regression oracle; see `REMOVED-SCRIPTS.md`.
